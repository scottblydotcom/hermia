Hermia Repository Analysis

Comprehensive Review of Repository Structure, Documentation & Best Practices

Repository: github.com/scottblydotcom/hermia | Date: May 11, 2026

Executive Summary

Hermia is an interactive LLM security evaluation TUI for local models. This analysis evaluated the repository's structure, documentation quality, CI/CD practices, and developer experience. The repository demonstrates exceptional security consciousness and documentation quality, significantly above average for open-source projects. Findings below are primarily polish-level improvements rather than critical issues.

1. Repository Structure

Clean Separation of Concerns

Well-organized with src/hermia/ for source, tests/ with unit/ and security/ subdirectories, and test-datasets/ for data.

Single-File Module Design

Each module has clear, single responsibility (metrics, runner, schemas, screens, etc.).

Modern Python Packaging

Uses pyproject.toml with hatchling build system.

Missing docs/ Directory

No centralized documentation folder for extended docs, architecture diagrams, or deep-dives.

Recommendation: Create a docs/ folder for architecture diagrams, extended framework mappings, and usage guides.

Scripts Folder Underutilized

The scripts/hermia file is alone in its directory.

Recommendation: Either add more utility scripts or relocate the single file to a more appropriate location.

No examples/ or sample-results/

As a TUI tool producing results, sample outputs would help users understand expected behavior.

Recommendation: Add sample result files or screenshots showing TUI output.

Test Datasets Organization

Only one JSON file in test-datasets/ currently, but may grow.

Recommendation: Consider organizing by dimension (security/, reasoning/, etc.) as the dataset expands.

2. Documentation Quality

Exceptional Root-Level Documentation

README, AGENTS.md, CLAUDE.md, CONTRIBUTING.md, SECURITY.md, CODE_OF_CONDUCT.md, CHANGELOG.md all present and comprehensive.

AGENTS.md Gold Standard

Detailed behavioral rules with "Never Do" and "Always Do" sections, grounded in actual git commits with SHA references.

CLAUDE.md AI Integration

Clear session start/close protocols for Claude Code integration.

Thorough Security Policy

Clear vulnerability reporting process with private reporting options.

Duplicate Rule Numbers in AGENTS.md

Rules 8 and 8a exist - inconsistent numbering scheme.

Recommendation: Renumber 8a to 9 and adjust subsequent numbering for clarity.

Missing Architecture Diagram

Complex framework mappings exist but no visual representation.

Recommendation: Add an architecture diagram (even ASCII art in README would help).

Broken Documentation Reference

CLAUDE.md references docs/security-framework-research.md which does not exist.

Recommendation: Either create the file or update the reference to point to existing documentation.

No Getting Started Guide

Beyond basic installation, there's no detailed usage documentation.

Recommendation: Create docs/usage.md with TUI screenshots and common workflows.

PyPI Future-Proofing

README notes pre-release status and roadmap to PyPI.

Recommendation: Add an "Installation from PyPI" section (commented or noted) for when published.

4. CI/CD & Automation

Dual Pipeline Design

Separate CI for lint/test and Security workflow for security scanning.

Extensive Security Scanning

gitleaks, trivy, bandit, pip-audit, guarddog (typosquatting detection).

GuardDog Integration

Sophisticated typosquatting detection with change filtering.

Minimal Permissions

Jobs explicitly scoped (e.g., contents: read only where needed).

No Release Automation

No workflow for automated PyPI publishing on version tags.

Recommendation: Consider workflow for automated PyPI publishing when ready.

No Auto-Labeling Bot

For external contributors, auto-labeling issues would help triage.

Recommendation: Consider a bot that auto-labels issues based on content.

No Stale Issue Management

Abandoned issues may accumulate over time.

Recommendation: Consider stale-bot workflow for issue hygiene.

5. Developer Experience

Clear Entry Points

Three CLI commands (hermia, hermia-regression, hermia-push) defined in pyproject.toml.

Organized Dependencies

[dev] and [grafana] optional dependencies properly grouped.

Beads Integration

Internal issue tracking with bd CLI documented.

Linting Configuration

Ruff and mypy configured with line length (100), strict mode, documented per-file ignores.

No Makefile or Task Runner

Common commands must be run manually.

Recommendation: Add a Makefile or taskfile.yml with targets: test, lint, security.

No Devcontainer or Docker

Tool requires Ollama locally - environment setup may vary.

Recommendation: Consider devcontainer or Docker compose for standardized environment.

No Pre-Commit Hook Config

AGENTS.md mentions pre-push hook but no .pre-commit-config.yaml for external contributors.

Recommendation: Add pre-commit configuration for external contributors.
