GUARDS + CO-STAR — Framework Reference

Scott Bly · Field CISO, SIS · author of GUARDS · GUARDS v1 published 2026-06-07, MIT licensed · part of the Hermia open-source LLM security evaluation project

The problem GUARDS addresses

A survey of 27+ prompt-engineering frameworks — CO-STAR, RISEN, ROSES, CRAFT, CRISPE, TIDD-EC, RTF, CARE, COAST, RACE, ReAct and others — found that all of them define positive intent: role, context, objective, style, format, audience, steps. None includes explicit dimensions for defensive instructions, attack-pattern detection, refusal protocols, or scope allowlists. GUARDS is a six-dimension standard for that missing defensive layer, plus a maturity model for assessing guardrail quality independent of model capability.

Scope. GUARDS addresses semantic prompt injection and operational drift — analogous to input validation in traditional AppSec. It does not defend against gradient-based token-optimization attacks, which need representation-layer defenses outside its scope. It is a conceptual schema, not a text-only artifact: the dimensions hold whether implemented as system-prompt text, fine-tuning data, or structured API parameters.

GUARDS — the six defensive dimensions

 DimensionWhat it specifies
GGoalThe defensive mission. Why the guardrail exists. A model that understands why it has boundaries holds them better under adversarial pressure than one given arbitrary restrictions.
UUnitWhat the agent is: identity/role, the trust posture it adopts toward each principal, session-state awareness, and voice. Sub-dimensions: Role · Principal/Trust · Session State · Voice. ("Unit" rather than "User" because User already names a principal type in OpenAI's Chain of Command.)
AActionsScope — permitted vs prohibited operations. An allowlist is stronger than a blocklist because it fails closed on novel requests.
RResponseOutput schema for both the success path and the refusal path, plus output grounding. Without a refusal schema the model improvises, which breaks downstream parsing.
DDetectTell the model what an attack looks like, in plain language, inside the prompt. The dimension most commonly absent from production system prompts.
SStopWhat to do when Detect fires — a typed refusal a downstream orchestrator can route on, not ad-hoc prose. Detect says "watch for this"; Stop says "and do this when you see it."

CO-STAR — the positive layer it composes with

 DimensionWhat it specifies
CContextWho the user is, the domain knowledge in play, the platform environment.
OObjectiveWhat the AI is there to accomplish — the task it should proactively do.
SStyleHow it writes: voice, register, conventions.
TToneEmotional register — collaborative, direct, formal.
AAudienceWho it is talking to, and their expertise level.
RResponseOutput format — length, structure, formatting preferences.
How the two compose: CO-STAR dimensions are additive (what to include); GUARDS dimensions are restrictive (what to constrain). They wrap the same system prompt from opposite directions — CO-STAR builds the positive space, GUARDS carves the negative space around it.
The shared "R" is a clean boundary, not a collision: CO-STAR's R governs format (length, structure); GUARDS' R governs refusal (how to say no, in schema). Similarly CO-STAR's O defines what to do; GUARDS' A defines what is out of bounds.
Why CO-STAR pairs cleanly: its six dimensions are almost entirely positive. Frameworks that already carry a constraint dimension — RISEN's "Narrowing", TIDD-EC's "Do/Don't" — overlap GUARDS territory and produce dimensional ambiguity when combined. CO-STAR does not.

Maturity model (SAMM-style)

LevelAssessment
M0Implicit / not addressed
M1Initial, ad-hoc — single sentence, minimum viable
M2Defined, consistent — explicit sub-dimensions present
M3Comprehensive — depth + quality criteria + automated CI/CD gating before a system prompt merges to main
TierProfile
BareM0–M1 across most dimensions — relies on base model training
ImplicitM2 in G/U/A/R, M0–M1 in D/S — boundaries without threat awareness
StandardM2+ across all six — full guardrailed posture
A GUARDS score is a maturity profile across six dimensions, not a single number. A prompt at M3/M3/M2/M2/M1/M0 is not equivalent to one at straight M2 — a missing Stop dimension is a known failure mode, not an averaging detail. SAMM was chosen over NIST CSF 2.0 tiers and CIS Implementation Groups for granularity: it offers explicit quality criteria as definition-of-done, and NIST's own documentation states its tiers are not maturity levels.

Where GUARDS sits — three orthogonal layers

LayerFrameworkQuestion it answers
Runtime / architectureAnthropic Zero Trust for AI AgentsHow is the agent contained, identified, observed?
Across-actor precedenceOpenAI Model Spec (Chain of Command)Whose instructions win when they conflict?
Within-prompt constructionGUARDSHow does the system author structure the prompt?

Each is necessary; none is sufficient alone. A GUARDS-structured prompt runs inside a Model-Spec-governed actor hierarchy inside a Zero-Trust runtime. The CO-STAR + GUARDS pairing is this same complementarity one level down, at the level of a single prompt.

Preliminary measurement (2026-07-21)

Approximately 14,000 stored evaluation responses spanning the point the GUARDS normalization entered the test corpus were re-scored with a single, identical grader, matched on model and test:

ObservationValue
Security-dimension pass rate, before vs after+7.6 percentage points (95% CI [6.3, 8.9])
Direction of the grader revision itselfStricter — 173 historical passes became failures; zero failures became passes
Breadth19 of 23 models improved
Dimensions targeted by GUARDSrouting +16.0, security +7.6, constraint +6.7
Dimensions not targetedreasoning −4.6, memory −2.0, domain −1.6, tool-use −0.7

Two things make this more interesting than the headline number. First, the grader moved in the opposite direction — it became harsher, so it cannot manufacture an improvement, only suppress one. Second, the result is a trade-off rather than a uniform gain: the dimensions GUARDS targets improve while untargeted capability dimensions drift slightly negative, consistent with defensive instruction consuming attention budget.

Stated limitations. This is observational, not a controlled experiment, and does not replace the ablation at step 3 above. The corpus commit that introduced the GUARDS normalization also bundled adversarial-framing changes to two tests, so GUARDS is not cleanly isolated from them. Inference hosts, hardware backends, and engine versions were not held constant across the comparison window; sample sizes are unequal; two models moved against the effect and are unexplained. The correct reading is that a controlled ablation is now well motivated — not that causation has been demonstrated.
