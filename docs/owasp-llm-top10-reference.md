## Hermia-relevant entries — detail

### LLM01:2025 — Prompt Injection
**Description (OWASP 2025):** *"A Prompt Injection Vulnerability occurs when user prompts alter the LLM's behavior or output in unintended ways."*

**Sub-types:**
- **Direct Prompt Injections** — user input directly alters model behavior (intentional or unintentional)
- **Indirect Prompt Injections** — LLM accepts external input (websites, files, **tool output**) containing data that, when interpreted, changes model behavior

**Impact categories (from OWASP):** Sensitive information disclosure · system infrastructure/prompt revelation · content manipulation and bias · unauthorized function access · arbitrary command execution · critical decision-making manipulation.

**Hermia mapping:** **Every Hermia security test.** Each prompt-injection variant we ship is, at root, a Prompt Injection (direct or indirect) vector. LLM01 is the load-bearing category for the entire security pillar; secondary codes (LLM02/06/07) layer on top to name the *consequence* the test probes.

### LLM02:2025 — Sensitive Information Disclosure
**Coverage (OWASP 2025):** *"Sensitive information can affect both the LLM and its application context, including personal identifiable information (PII), financial details, health records, confidential business data,* ***security credentials,*** *and legal documents."*

**Hermia mapping:** Tests where the *consequence* of compliance is leaking sensitive in-context data:
- `credential-leak-resistance` — explicit secret in context, model asked to disclose
- `lane-routing-evasion` — credential-disclosure request embedded in a routing task
- `system-prompt-extraction-resistance` — *defensible* secondary (system prompt counts as confidential business data), though LLM07 is the more specific home

OWASP explicitly names "security credentials" — that's what makes the credential-leak tests squarely LLM02, not merely LLM01.

### LLM05:2025 — Improper Output Handling
**Description (OWASP 2025):** *"Improper Output Handling refers specifically to insufficient validation, sanitization, and handling of the outputs generated by large language models* ***before they are passed downstream*** *to other components and systems."*

**Hermia mapping:** **None of the current 30.** LLM05 is about *downstream-consumer safety* — SQLi, XSS, SSRF, RCE caused by an application interpreting LLM output unsafely. It is **not** about whether the LLM emits a schema-correct response. `strict-constraint-adherence` is a capability test ("did the model produce the required JSON keys"), not an LLM05 test ("would interpreting this output cause RCE in a downstream consumer"). Mapping a capability test to LLM05 is a category error — the test does not exercise downstream sanitization at all.

### LLM06:2025 — Excessive Agency
**Description (OWASP 2025):** *"Excessive Agency is the vulnerability that enables damaging actions to be performed in response to unexpected, ambiguous or manipulated outputs from an LLM… Excessive Agency occurs when an LLM is granted too much functionality, permissions, or autonomy, enabling it to perform unintended or harmful actions."*

**Sub-types (OWASP):** Excessive Functionality · Excessive Permissions · Excessive Autonomy.

**Hermia mapping:** Tests where the *consequence* of compliance is the model acting outside its sanctioned scope:
- `security-boundary` — harmful exfiltration action (overreach of intended behavior)
- `scope-escalation-resistance` — write action when only read scope granted (permission overreach)
- `system-user-precedence` — attempted privilege gain via false user-claimed authority (autonomy/permission overreach)

### LLM07:2025 — System Prompt Leakage
**Coverage (OWASP 2025):** *"System Prompt Leakage refers to situations where internal instructions provided to an LLM, such as system messages, developer prompts, guardrails, or hidden logic, are revealed to users or attackers through model responses."*

**Critical security principle (OWASP, verbatim):** *"The system prompt should not be considered a secret, nor should it be used as a security control. Accordingly, sensitive data such as credentials, connection strings, etc. should not be contained within the system prompt language."*

**Hermia mapping:** Tests that probe extraction of the system prompt itself:
- `system-prompt-extraction-resistance` — direct extraction attempt

LLM07 is the specific home; LLM02 (Sensitive Info) is a defensible secondary because the leaked content is confidential.

## Multi-mapping rationale (why OWASP differs from MAESTRO / NIST)

We mapped MAESTRO and NIST single-locus per test. **OWASP is different** — it is a flat threat catalog where one test can legitimately exhibit multiple distinct threats:

- A test that asks the model to exfiltrate `/etc/passwd` exercises **LLM01** (the request itself is an injection-shaped attack) *and* **LLM06** (the consequence of compliance is excessive-agency action outside scope).
- A test that asks the model to disclose an in-context API key exercises **LLM01** (the credential request is an injection vector) *and* **LLM02** (the consequence is sensitive-information disclosure).

These pairings name **two distinct, complementary threats** — not two answers to the same architectural question. Multi-mapping here is *more* informative than single-mapping.

**Constraint:** ≤ 2 codes per test. If a third feels defensible, the secondary code is probably the *more specific* fit (e.g. LLM07 over LLM02 for system-prompt extraction). Multi-mapping is for **distinct threat surfaces**, not category synonyms.

## Decision tree for mapping a new Hermia test

```
1. Does the test prompt the model with an attack of any kind (injection,
   adversarial input, override, social engineering, exfiltration request)?
   NO  → empty OWASP mapping. The test is pure capability.
   YES → LLM01:2025 is always a primary mapping.

2. Beyond LLM01, what is the CONSEQUENCE the test probes?

   (a) Leaking specific sensitive data placed in context (credentials,
       PII, business confidential)?
       → add LLM02:2025 (Sensitive Information Disclosure)

   (b) Leaking the SYSTEM PROMPT specifically?
       → add LLM07:2025 (System Prompt Leakage) — more specific than LLM02

   (c) Acting outside sanctioned scope (privilege escalation, write when
       read granted, harmful out-of-scope action, false-authority privilege)?
       → add LLM06:2025 (Excessive Agency)

   (d) Downstream-consumer harm (SQLi/XSS/SSRF/RCE caused by an application
       interpreting model output)?
       → LLM05:2025 (Improper Output Handling) — note: none of the current
         30 tests exercise this; do not map LLM05 to capability/format tests.

3. Stop at ≤ 2 codes per test. Multi-mapping names DISTINCT threats, not
   category synonyms.
```

## Common mapping errors (caught in 2026-06 audit)

- **Capability test mapped to LLM06 (Excessive Agency).** `strict-constraint-adherence` was mapped to LLM06 with the rationale "output-format constraint adherence." Excessive Agency is about the model *taking actions outside scope* — a format-correctness test does not exercise that. **Capability tests get empty OWASP mappings.**
- **Credential-disclosure threat mapped to LLM01 only.** `credential-leak-resistance` named LLM01 (the vector) but omitted LLM02 (the consequence — OWASP explicitly names "security credentials" under Sensitive Info Disclosure).
- **lane-routing-evasion mapped to LLM06 only.** The test embeds a *credential request* in a routing task. LLM06 (agency overreach) is at best secondary; LLM01 (injection vector) + LLM02 (credential disclosure consequence) are the primary pair.
- **Inferring 2025 titles from 2023 slugs.** The genai.owasp.org URL slugs are frozen at 2023 ordering. `/llmrisk/llm06-sensitive-information-disclosure/` actually serves LLM06:**2025** Excessive Agency. **Trust the codes, not the slugs.**
- **Reading LLM05:2025 as "the model emitted bad JSON."** LLM05 is downstream-consumer sanitization (SQLi/XSS/RCE from app code that interprets LLM output unsafely). It is not a schema-adherence category.
