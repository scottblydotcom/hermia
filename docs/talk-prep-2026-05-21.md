# Hermia Talk Prep — ~2026-05-21

## Framing & Positioning

### What Hermia Is (in one sentence)
"Snort / Wireshark for the LLM era." The inference stack — model binary, runtime, hardware, driver stack — is the unit of analysis. Nobody else treats it that way.

### The 10/10 Positioning Move
**Inference Stack as Unit of Analysis.** Not model benchmarks. Not prompt engineering. The specific model binary, running on a specific runtime, on specific silicon, with a specific driver stack. A ROCm update can flip a security test from PASS to FAIL. That's not theoretical — we built the telemetry to catch it.

### v0.1 Scope: Say This Explicitly, Before Someone Asks
v0.1 is **single-turn, structured behavioral eval.** It relies on **structural determinism**: JSON schema compliance, key presence, MITRE/OWASP label matching. It is NOT agentic. Do not call it agentic. Nuanced intent evaluation is v0.3. Be explicit about this scope before a savvy security audience asks — it reads as honest, not as a limitation.

Good language: "deterministic foundation," "single-turn structural integrity," "structural robustness eval."
Bad language: "agentic eval suite" (will be called out).

### "Non-Commercial" → "Vendor-Agnostic"
Saying "we don't sell anything" while describing a consultancy flywheel reads as bait-and-switch.

Better: "Hermia is the open standard for the consultancy's methodology. We give the framework away free to prove we're the best marksman in the room. Vendor-agnostic — works against any Ollama endpoint, any hardware backend."

### Hardware Telemetry → Resource Exhaustion as Security Control
The security framing for VRAM telemetry: adversarial prompt → VRAM spike → OOM → local DoS = **availability attack** (CIA triad: Availability). Hermia captures the data that would detect this.

Be honest: detection logic (alerting on VRAM anomalies) is vNext/research. The telemetry is already there. This is the bridge from "perf metric" to "security control."

### Divergence Detection: The Killer Feature — Lead With It
A ROCm update changed a security pass/fail. That proves why local-first testing is mandatory. Vendors don't tell you when a driver update changes behavioral output. Only you can detect it, and only if you're running evals against the actual inference stack you deploy.

Lead with this even though the full implementation (regression dashboard, automated diff alerting) is vNext. The claim is defensible right now because the JSONL audit trail already makes manual divergence analysis possible. Nobody else in the space is making this claim.

## Demo Design

### Pre-Demo: Pin the Ollama Version
An Ollama API change three days before a talk is a real failure mode. Before the talk:
- Note the exact Ollama version on every demo endpoint
- Include the version on the Technical Requirements slide
- Use hermia-bo1 preflight output (`SEC ⚠` CVE warnings) as the **first screen the audience sees** — immediate signal that Hermia knows its attack surface

### The Goldilocks Scenario (Core Demo — ~10 min)
Run 2–3 models, injection-resistance tests only (OWASP LLM01 / MITRE AML.T0051).

**The story arc:**
1. Smaller model **fails** — prompt injection, behavioral override, LLM01 mapping visible
2. Larger model **passes** — same test, structural compliance confirmed
3. Hardware telemetry running throughout — tokens/sec, VRAM or unified memory, elapsed time

**The punchline:** "Here's the vulnerability. Here's the framework. Here's which model you should deploy. And here's what your hardware was doing during the test."

Reinforce: this is single-turn structural integrity, not agentic. Say it before it's asked.

Candidate model pair: `llama3.2:3b` (fails) → `qwen3:8b` (passes). qwen3:8b scored 100% on injection resistance at 175 t/s on Eric's 5090.

### The Wireshark Moment (Fleet Mode — if time permits)
Run the same model (e.g., `qwen3:8b`) against two backends simultaneously via fleet mode:
- Eric's 5090 (CUDA, RTX 5090, 96GB RAM)
- M3 Pro (Apple Silicon / Metal, unified memory)

**If any security test diverges between backends:** that IS the demo. Visceral proof that inference stack variance is real.

**If results are identical:** the side-by-side hardware telemetry (CUDA VRAM vs. unified memory footprint, tokens/sec delta) still proves the architectural point — same model, different silicon, different behavior envelope.

### Addressing the "Race Condition" Question
Gemini flagged JSONL writes as a potential race condition. Correct pushback if it comes up:
- Fleet mode = one Hermia process fanning out HTTP to many Ollama targets
- Single-writer property holds — one process, one results directory
- Only becomes a real concern if multiple Hermia clients write to shared storage (not in scope through v0.2)
- The flag was wrong for current architecture; design is deliberate
